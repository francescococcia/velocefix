# Lessons from Francesco's past hackathons

Apply these when scoring ideas, locking a product, and writing the pitch. They come from prior events (including judge feedback that "needs this model" was once the weakest criterion) and the current event playbook.

1. **One product and one user type.** Two-sided products (two buyers, or "both sides of the marketplace") usually halve the score. Pick a single named user and build only for them.
2. **Test the premise against real behaviour.** Ask whether people actually choose or work this way today. A neat technical rule loses to what practitioners already do (and already hate). Treat a single conversation, including a judge chat, as a hypothesis until it is checked.
3. **If a track brief describes a winning demo, build exactly that first.** The official "what a winning demo looks like" line is the spec, not a suggestion.
4. **Go deep on 1–2 sponsor techs, not three or more.** Sponsor judges reward depth in their own stack. Extra integrations dilute the demo and usually half-work.
5. **Make "why Grok Bot" visible.** At a past event, "needs this model" was the weakest criterion. The demo must show why this is a Grok Bot teammate (and Cursor to build it), not a generic chatbot wrapper.
6. **Real data entered tonight beats example or scraped data.** If a criterion asks for real or traceable data, collect it after the input form exists. Do not invent a "live" feed.
7. **Max about three new integrations solo**, each time-boxed, each with a typed or static fallback. Voice, memory graphs and extra APIs get a 20–30 minute box and must degrade gracefully.
8. **Too many features hurt a 2-minute demo.** One path, three to five beats, nothing extra if the core is not live by T-90 minutes.
9. **Show the agent choosing and deterministic code verifying it on screen, with live data.** Judges praise an agent that proposes plus code that checks, both visible, both cited.
10. **Open the pitch with a named user's problem** and why existing apps or AI chats do not solve it, before any features. Innovation and impact points are won here.
11. **Say the privacy design out loud** when you handle location, documents, photos, voice or personal data (what is stored, what is not, what is sent, what is redacted).
12. **Do an honesty pass on example data.** Say what is synthetic, what was entered tonight, and which links not to click. Judges punish discovered fakes more than admitted gaps.
13. **Meet users where they already are** (email, deal chat, existing tools), rather than only as a standalone app — or at least show that version in the demo.

## Time boxes that also held up

- Feature freeze about 40 minutes before the official freeze; backup 60–90s video against the live URL; submit before T-10.
- Debug a single bug for 15 minutes, then cut it or swap to the fallback.
- Official tonight: code freeze and submission 23:00 Europe/London; aim for a working MVP by 22:10; Top 5 live demos 23:30, 2 minutes each.
